## Findings

### CRITICAL (2)

#### C1 · Sourcemaps in productie-build = code-disclosure

- **Locatie**: `vite.config.ts:17` (`sourcemap: true` zonder env-gate). `dist/assets/index-*.js.map` + `supabase-*.js.map` aanwezig na build.
- **Beschrijving**: `npm run build` produceert source-maps die alle TypeScript-bron, lokale variabelen, comments en exact logica reverse-mappen. GitHub Pages serveert ze publiek; aanvallers kunnen `view-source` openen en zien volledige source.
- **Exploit**: aanvaller leest precieze RLS-bypass-pogingen, vendor-IDs, alle Edge-Function-URLs, business-logica voor change_request-validatie. Maakt black-box → white-box testing.
- **Mitigatie**: zet `sourcemap: false` voor productie. Behoud voor `npm run dev` via `sourcemap: process.env.NODE_ENV !== 'production'`. Hergenereer `dist/` zonder maps + verifieer `dist/assets/*.map` is leeg.

#### C2 · Geen Data Processing Agreement (DPA) gedocumenteerd

- **Locatie**: ontbrekend in `docs/`
- **AVG-artikel**: Art. 28(3) — schriftelijke processor-overeenkomst verplicht
- **Beschrijving**: Supabase, GitHub Pages, toekomstige SMTP-provider en SharePoint zijn allemaal **processors** die BSN/IBAN verwerken namens Noordhoff (controller). Zonder geformaliseerde DPA's is Noordhoff aansprakelijk voor processor-acties.
- **Exploit**: niet technisch — juridisch. Bij Autoriteit-Persoonsgegevens-incident kan Noordhoff niet aantonen dat afspraken met Supabase contractueel zijn vastgelegd. Boetes tot 20M EUR of 4% wereldwijde omzet.
- **Mitigatie**: Infinitas IT / Noordhoff Legal:
  1. Accepteer Supabase Standard DPA via Trust Center (`supabase.com/legal/dpa`)
  2. GitHub Pages DPA via Microsoft Customer Agreement
  3. Tekenen DPA met SMTP-provider zodra gekozen
  4. Document in `docs/DATA_PROCESSOR_AGREEMENTS.md` met datum + verantwoordelijke

### HIGH (13)

#### H1 · JWT in `localStorage` met onvoldoende strikte CSP — ✅ CLOSED iter 9

- **Status**: Productie-CSP (build-time gegenereerd via `vite.config.ts:strictCspPlugin`) heeft `unsafe-inline` weggehaald uit `style-src` en `style-src-elem`. Alleen `style-src-attr 'unsafe-inline'` blijft staan voor de JS-API (`el.style.X = value`). Inline `<style>`-blokken zijn nu CSP-geblokkeerd; CI verifieert dit op elke build.
- **Locatie origineel**: `src/lib/supabase.ts:42` (`persistSession: true`) + `index.html` CSP `style-src 'self' 'unsafe-inline'`
- **Beschrijving**: Auth-tokens worden in `localStorage` opgeslagen. Niet HttpOnly, niet Secure-cookie. Een DOM-XSS in om het even welk pad ⇒ token-exfiltratie ⇒ account-overname.
- **Exploit**: aanvaller injecteert via een onbedoeld `innerHTML`-pad een script dat `JSON.parse(localStorage.getItem('sb-...-auth-token')).access_token` exfiltreert. Werkt zolang CSP niet 100% script-injectie blokkeert. Huidige CSP `script-src 'self'` is goed, maar `style-src 'unsafe-inline'` opent inline-styles waar exfiltratie via `background:url()` met `:has()` selector mogelijk is.
- **Mitigatie**:
  - Blijf op `localStorage` (Supabase JS SDK default) maar **verhardt CSP**: voeg `connect-src 'self' https://qcqjurglmrhdiuhawfee.supabase.co` (al deels), explicit `frame-ancestors 'none'`, verwijder `unsafe-inline` van `style-src` door gegenereerde CSS te gebruiken in plaats van inline.
  - Daarnaast: enforce alle `innerHTML`-mutaties via `eslint-plugin-no-unsanitized` (al actief).
  - Lange termijn: overweeg server-side cookie-flow via Supabase Auth Helpers (vereist SSR, niet feasible voor GitHub Pages — accepteer of overweg Cloudflare Workers).

#### H2 · Geen MFA voor admin-account

- **Locatie**: `auth/sso.ts` placeholder uit, `decideAccess()` accepteert wachtwoord-only login voor admin
- **AVG-artikel**: Art. 32(1)(b) — passende organisatorische maatregelen
- **Beschrijving**: Admin logt in met email + password. Wachtwoord-reset gaat per email (single-factor). Phishing-gevoelig. Compromise = volledige database-access via admin-RLS-policy.
- **Exploit**: phishing-mail naar Patrick met "reset uw wachtwoord" → click → fake login-pagina → captures password → attacker logt in op productie als admin → exporteert alle PII via CSV-export.
- **Mitigatie**:
  - **Korte termijn**: Supabase native TOTP MFA inschakelen voor admin-account (`supabase.auth.mfa.enroll({factorType: 'totp'})`).
  - **Productie**: Microsoft Entra ID SSO afronden zodra Infinitas IT Azure-tenant levert. Entra dwingt MFA conform tenant-policy.

#### H3 · Geen Privacy Policy / informatieplicht (Art. 13 AVG)

- **Locatie**: ontbreekt
- **AVG-artikel**: Art. 13-14 — informatie aan betrokkene bij verzameling
- **Beschrijving**: Auteurs krijgen geen info over: welke data verzameld, doel (royalty-uitbetaling = contract art. 6(1)(b)), bewaartermijn, sub-processors, rechten (access/correction/erasure/portability), DPO-contact.
- **Exploit**: niet technisch. Bij klacht of AP-onderzoek kan Noordhoff niet aantonen aan informatieplicht te hebben voldaan.
- **Mitigatie**: maak `docs/PRIVACY_POLICY.md` of publiceer op `mijn-noordhoff.nl/privacy.html`. Link in footer van portaal. Bevat minimaal de 9 punten van Art. 13(1-2).

#### H4 · Geen Right-to-Erasure flow

- **Locatie**: ontbreekt — geen delete-flow voor auteurs
- **AVG-artikel**: Art. 17
- **Beschrijving**: Auteurs kunnen niet hun eigen account laten verwijderen. Geen admin-flow om hard-delete uit te voeren. Bij verzoek "vergeet mij" moet admin handmatig SQL uitvoeren — ongedocumenteerd, foutgevoelig.
- **Exploit**: betrokkene dient verzoek in (verplicht binnen 30 dagen reageren). Noordhoff kan niet uitvoeren binnen termijn → klacht bij AP.
- **Mitigatie**:
  - Edge Function `delete-author` (admin-only): hard-DELETE uit `authors` (`ON DELETE CASCADE` ruimt al op), `auth.admin.deleteUser`, INSERT in `audit_deletions` archief-tabel.
  - Document procedure in `docs/PRIVACY_POLICY.md`.
  - Optioneel: soft-delete via `deleted_at` voor 30-dagen-grace-period.

#### H5 · Geen Data Retention Policy

- **Locatie**: niet gedocumenteerd, geen automatic purge-job
- **AVG-artikel**: Art. 5(1)(e) — opslagbeperking
- **Beschrijving**: Onbepaalde bewaring van BSN/IBAN. NL-wetgeving vraagt 7 jaar voor belastingadministratie + Boekhoudwet, maar daarna **moet** verwijderd worden. Geen `pg_cron`-job, geen retention-policy.
- **Mitigatie**:
  - Schrijf retention in `docs/RETENTION_POLICY.md`: auteur-data 7j na contract-einde, login_history 1j, change_requests 3j, statements 7j (fiscaal).
  - Implementeer maandelijkse Edge Function (gepland via `pg_cron` of GitHub Actions cron) die expired rows verwijdert + audit-archiveert.

#### H6 · Geen DPIA voor BSN-verwerking

- **AVG-artikel**: Art. 35 — DPIA verplicht voor high-risk processing (BSN = high-risk per AP-lijst)
- **Beschrijving**: Geen Data Protection Impact Assessment uitgevoerd of gedocumenteerd. AP kan deze inzien.
- **Mitigatie**: Infinitas IT / Noordhoff DPO doorloopt EDPB-template. Outcome bewaren in `docs/DPIA-2026.md`. Bevat: doel, lawful basis, dataminimalisatie-rationale, risico-matrix, mitigaties.

#### H7 · CSV-export bevat niet-geminimaliseerde dataset

- **Locatie**: `supabase/functions/export-authors-csv/index.ts:38-54` (15 kolommen, alle PII)
- **AVG-artikel**: Art. 5(1)(c) — dataminimalisatie
- **Beschrijving**: Elke export-CSV bevat álle 15 velden incl. BSN/IBAN voor élke gewijzigde rij — ook als alleen telefoonnummer is veranderd. CSV gaat naar SharePoint (buiten Supabase-control).
- **Exploit**: SharePoint-incident of compromised Noordhoff-account ⇒ alle BSN's gelekt, niet alleen wijzigingen.
- **Mitigatie**: zoals al genoemd in `README.md` sectie 6b ("open punt"): implementeer diff-tracking via `change_requests`-tabel en stuur alleen daadwerkelijk-gewijzigde velden + `vendor_id` als sleutel. Vereist nieuwe Edge Function-logica.

#### H8 · Geen malware-scan op file-uploads

- **Locatie**: `src/views/admin/statement-upload.ts` + `src/views/tabs/expenses.ts` — alleen MIME-type-check (kan gespoofed)
- **AVG-artikel**: Art. 32 — passende beveiligingsmaatregelen
- **Beschrijving**: Auteur kan PDF uploaden met `Content-Type: application/pdf` maar de bytes bevatten een EXE/ZIP. Storage slaat het op. Admin downloadt later → potentieel virus/exploit.
- **Mitigatie**:
  - Client-side: lees magic-bytes (PDF = `%PDF-`) vóór upload.
  - Server-side: ClamAV-Edge-Function die opload triggert + scan uitvoert + bestand quarantine-bucket bij hit.
  - Document procedure in SECURITY.md.

#### H9 · Audit-trail incompleet (statement-upload, expense-upload, CSV-import) — ✅ CLOSED iter 9

- **Status**: opgelost in iter 9 via `0012_audit_actions.sql`. `audit_actions` tabel met 17-waardig action-type enum, indexes, RLS-policy (alleen admin SELECT), `audit_strip_pii()` helper voor BSN/IBAN-masking. Vier DB-triggers (SECURITY DEFINER) op `authors`, `change_requests`, `payments`, `expenses` schrijven before/after JSONB-diffs. Edge Functions `create-accounts` en `import-authors-csv` instrumented voor `author_invited`, `author_reminded`, `csv_imported`, `csv_exported` events die niet door triggers worden gevangen. PII (BSN/IBAN) wordt automatisch gemaskeerd in JSONB-snapshots via `audit_strip_pii()`.
- **Locatie origineel**: tabellen `payments`, `expenses` — geen `created_by` of `audit_actions`-koppeltabel

#### H10 · Geen rate-limiting op Edge Functions — ✅ CLOSED iter 9

- **Status**: opgelost in iter 9 via `0013_rate_limits.sql`. `rate_limits` tabel met atomic `check_rate_limit(actor, action, max, window_seconds)` functie via INSERT...ON CONFLICT (geen race-condities). Alle drie Edge Functions instrumented met per-actor/per-uur limits: create-accounts 60/uur, import-authors-csv 10/uur, export-authors-csv 30/uur. Overschrijding ⇒ HTTP 429.
- **Locatie origineel**: alle drie Edge Functions
- **Mitigatie origineel**: implementeer simpele throttle in Edge Function: lees `last_action_at` per `caller_id` uit een `rate_limits` tabel; reject als `< 60s` voor sensitive actions. Ook frontend-debounce op admin-buttons (1-sec cooldown) als UX-laag.

#### H11 · CORS te permissief in productie

- **Locatie**: alle Edge Functions, `ALLOWED_ORIGINS` array bevat `http://localhost:5173` + `https://singaporecity.github.io`
- **Beschrijving**:
  - `localhost:5173` is dev-origin — moet niet in productie-deploy.
  - `singaporecity.github.io` is oude demo-domain (al gepland te archiveren) — niet relevant in productie.
  - **Ontbreekt**: `https://mijn-noordhoff.nl` zelf.
- **Exploit**: aanvaller kan vanaf eigen webpage met `Origin: http://localhost:5173` request sturen — CORS-check passeert. Alleen mitigatie is JWT-vereiste, maar ongewenst-cross-origin is gevaarlijk.
- **Mitigatie**:
  - Per environment: dev-functies hebben localhost; productie-functies alleen `mijn-noordhoff.nl`.
  - Hardcoded array vervangen door env-var `ALLOWED_ORIGINS` per Supabase-environment.
  - Verwijder `singaporecity.github.io` overal; voeg `https://mijn-noordhoff.nl` toe.

#### H12 · Geen branch-protection op `main`

- **Locatie**: GitHub repo-settings (te verifiëren door Patrick)
- **Beschrijving**: Direct push naar `main` mogelijk zonder PR + zonder code-review. Husky pre-commit-hook draait wel, maar lokaal — kan met `--no-verify` worden omzeild.
- **Exploit**: developer-machine-compromise ⇒ aanvaller pusht `main` met malicious code; GitHub Pages deployt direct naar productie.
- **Mitigatie**: GitHub repo Settings → Branches → Branch protection rule on `main`:
  - Require pull request before merging (zelf-merge OK voor solo-dev maar PR forceert review)
  - Require status checks to pass (CI green)
  - Require conversation resolution
  - Restrict who can push to matching branches (alleen admins)

#### H13 · SMTP-blokker (al gedocumenteerd)

- **Locatie**: `README.md` sectie 8 — al benoemd, maar herhaal hier voor volledigheid
- **Beschrijving**: Supabase mailer 3 mails/uur, `noreply@mail.app.supabase.io`, geen SPF/DKIM/DMARC. Onbruikbaar voor 5000+ mails/maand productie.
- **Mitigatie**: zoals gedocumenteerd — Resend/SendGrid/SES kiezen, DNS-records configureren op `noordhoff.nl`, dan SMTP-config in Supabase Dashboard.

### MEDIUM (11)

#### M1 · `last_exported_at` kan door auteur worden gemanipuleerd ✅ CLOSED iter 8

- **Locatie**: `0008_data_exports.sql:115-118` (eigen comment erkent het)
- **Beschrijving**: Bestaande `authors_update_own` policy laat auteur eigen rij UPDATE-en. Geen column-level privilege. Auteur kan via PostgREST direct `update({last_exported_at: '2099-01-01'})` doen → eigen wijzigingen worden nooit naar NetSuite gesynchroniseerd.
- **Status**: opgelost in iter 8 via `0011_last_exported_at_lock.sql` — BEFORE UPDATE OF trigger reset OLD-waarde silent voor non-service-role callers.

#### M2 · `decideAccess()` race-condition tussen status-load en rendering

- **Locatie**: `src/auth/whitelist.ts:48-58` + `src/main.ts`
- **Beschrijving**: Frontend laadt `authors`-row eenmalig, rendert dashboard. Tussentijds kan admin de auteur op `pending_data` zetten — frontend weet dat niet, blijft renderen. RLS-policies blokkeren wel volgende API-calls met 403.
- **Exploit**: gestolen sessie blijft tot 1u (JWT-expiry) actief, ook als admin "deactiveert".
- **Mitigatie**:
  - Verkort JWT-expiry naar 15min via Supabase Auth setting.
  - On 403/401 from any API call: auto-logout via global error-handler.
  - Optioneel: Supabase Realtime subscription op eigen `authors`-row voor live status-update.

#### M3 · Recovery-mail email-enumeration ✅ CLOSED iter 8

- **Locatie**: `src/auth/password.ts:53-57` + `src/views/login.ts` forgot-flow
- **Beschrijving**: Forgot-password-form retourneert `{success: false}` voor onbekend email vs `{success: true}` voor bekend. Aanvaller kan emails enumereren door responses te observeren.
- **Status**: opgelost in iter 8. `requestPasswordReset()` retourneert nu altijd `{success: true}` ongeacht onderliggende fout — uniform respons voorkomt timing/response-based enumeration. Echte fouten worden niet gelogd in client (Supabase platform-logs heeft auth-events met IP voor forensisch onderzoek).

#### M4 · BSN unmasked in profile-edit-form ✅ CLOSED iter 7

- **Locatie**: `src/views/tabs/profile.ts` — `buildEditForm()` voor active-mode + onboarding-form
- **Beschrijving**: In view-mode is BSN gemaskeerd (`••••6789`). In edit-mode toont input volledige BSN onversleuteld in DOM. Auteur ziet eigen volledige BSN (niet kritiek, eigen data). Admin ziet BSN volledig in change-request-modal. Bezwaar: dataminimalisatie + screenshare-risico.
- **Status**: opgelost in iter 7. BSN is na eerste invoer onwijzigbaar (DB-trigger 0010 + Edge Function skip + frontend `IMMUTABLE_FIELDS`). BSN-veld is volledig verwijderd uit `change_requests`-flow. In active-mode is BSN masked, met "Toon BSN" 30s-toggle voor inzagerecht eigen data.

#### M5 · Geen application-level encryption van BSN/IBAN

- **Locatie**: `authors`-tabel — kolommen `bsn`, `bank_account` opgeslagen in plain text (Supabase doet wel volume-level disk-encryption)
- **AVG-artikel**: Art. 32(1)(a) — encryption appropriate to risk
- **Beschrijving**: Bij compromise van Supabase-managed disks of database-export is BSN onmiddellijk leesbaar. Best-practice voor BSN is application-level encryption (decryptie alleen wanneer nodig).
- **Mitigatie**: implementeer `pgcrypto`-encrypted-at-rest voor BSN/IBAN. Decrypt alleen via `is_admin()`-policy. Hoog implementatie-werk; documenteer als known-limitation als pilot-trade-off.

#### M6 · Geen logout-revocation — JWT blijft geldig tot expiry

- **Locatie**: `src/auth/session.ts` — `signOut()`
- **Beschrijving**: `supabase.auth.signOut()` verwijdert lokale token, maar JWT (1u expiry) blijft server-side geldig. Aanvaller met gestolen token kan nog 1u door. Refresh-token (30d) kan nieuwe access-tokens generen — als refresh-token gestolen is, valt de session weken niet om.
- **Mitigatie**:
  - Verkort access-token expiry naar 15min.
  - Bij signOut: roep ook server-side revoke aan via Supabase Auth admin API (revoke-token).
  - Documenteer in `docs/SECURITY.md` token-lifecycle.

#### M7 · Geen CSRF-token op Edge-Function-calls

- **Locatie**: alle Edge Functions
- **Beschrijving**: Edge Functions accepteren JWT in `Authorization: Bearer` header. Aanvaller met cross-origin script kan via `fetch()` met `credentials: 'include'` request sturen — maar JWT zit in localStorage niet in cookie. Browser stuurt JWT NIET automatisch. Dus CSRF-impact is beperkt.
- **Echter**: als ooit naar cookie-flow gemigreerd wordt, is CSRF acuut.
- **Mitigatie**:
  - Bij blijven op localStorage-JWT: geen actie, beperkt risico.
  - Verifieer SameSite=Strict op alle Supabase-cookies (komt later via cookie-config).
  - Noteer als design-trade-off in `docs/SECURITY.md`.

#### M8 · CSV-import: geen transactie-wrapping bij bulk — ✅ CLOSED iter 9

- **Status**: opgelost in iter 9 via `0014_import_authors_rpc.sql`. Per-rij upsert wordt nu atomair afgehandeld via Postgres-functie `import_author_row()` — `SELECT ... FOR UPDATE` lockt bestaande rij + INSERT/UPDATE in één transactie. Geen race-window meer tussen `existing-check` en `apply`. BSN-immutability is intern in de RPC verwerkt (returnt `bsn_skipped` ipv falen). Edge Function refactored om alleen RPC te callen — Insert-mapping verwijderd uit Deno-code.
- **Locatie origineel**: `import-authors-csv/index.ts:165-220` — loop met INSERTs/UPDATEs

#### M9 · CSV-import: geen content-type / size-validatie ✅ CLOSED iter 8

- **Locatie**: `import-authors-csv/index.ts:130-145` — accepteert `body.csv` zonder grootte-check
- **Beschrijving**: Aanvaller stuurt 100MB CSV → Edge Function laadt in geheugen → memory-limit hit, mogelijk crash van function-instance.
- **Status**: opgelost in iter 8. `Content-Length` header gecheckt vóór parsing + na JSON-parse ook `csv.length` size-guard met max 10 MB. Returnt 413 Payload Too Large.

#### M10 · `enforce_onboarding_transition`-trigger geen audit-log — ✅ CLOSED iter 9

- **Status**: opgelost in iter 9 via `0012_audit_actions.sql`. `audit_authors_change` trigger draait AFTER UPDATE op `authors` en logt `author_status_changed` events naar `audit_actions` met before/after JSONB-diff (PII gemaskeerd via `audit_strip_pii()`). Werkt voor zowel admin-flows als service-role Edge Function-flows.
- **Locatie origineel**: `0006_onboarding_status.sql:120-160`

#### M11 · Wachtwoord-policy zwak / niet geforceerd

- **Locatie**: Supabase Auth-instellingen (default min length 6 chars)
- **Beschrijving**: Standaard-Supabase-policy is minimaal 6 chars. Charlotte's testpassword is `CharlotteTest123` — 16 chars, oké. Maar productie-auteurs kunnen trivial wachtwoorden kiezen.
- **Mitigatie**: Supabase Dashboard → Authentication → Policy → minimum length 12 chars + require uppercase/lowercase/digit/special. Of via custom hook met `zxcvbn`-strength-score.
